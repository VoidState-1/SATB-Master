# 教材谱例校准三阶段工作流

本流程采用三阶段架构，将**基线冻结**、**AI 自主迭代爬坡**与**人工仲裁验收**解耦：第一阶段产出可追溯的候选数据与冻结基线，不改代码；第二阶段由 `GPT 6.2 Astra`（编排与复核）、多实例 `GPT 6.2 Sol`（并行执行）与 `Gemini 4 neon`（按需由用户转述问题和意见，提供独立外部交叉验证）在硬护栏约束下自主迭代；第三阶段由人工按里程碑节奏低频介入，裁定争议池高价值问题、执行盲抽检并核准最终标准用例。模型判断、教材依据与测试通过均不能代替人工核准。

数据入口见 [SATB 简写接口](./score-text.md)，批次目录见 [StandardCase](../StandardCase/README.md)，规则迭代与代码维护细则见 [教材规则检查器的迭代约定](./textbook-rule-calibration.md)。

在含教材资料的本地工作区，`StandardCase/教材校准工作流.md` 记录完整操作流程与最新基线进度，`StandardCase/验收指标与分母规范.md` 定义分母前置门槛与 M1/M2 目标，`StandardCase/研究工具使用手册.md` 提供命令行与工具速查。教材查证从 `StandardCase/Library/教材目录.html` 或 `library.cmd search` 开始，逐项回到所属扫描本的原页。四条项目主线与配套演进设计见 [项目开发主线](../DesignDocs/project-mainlines.md)。

## 第一阶段：建库、转写、基线比对与冻结

### 1. 转写和独立标注

- 当前答案原谱主要来自黄虎威《和声学习题解答》（上、下册），理论与规则口径主要查证斯波索宾等《和声学教程》。完整连续答案用于整题评测，独立短题与片段也可评测上下文充分的部分，艺术作品单独存放。
- 记录书名、版本指纹、PDF 物理页、书内印刷页、题号、谱例范围与完整裁图，核实相邻正文归属，并以原题键 `parentQuestion` 去重。
- 转写调号、拍号、四声部、绝对书写音高、时值、起奏、延音与休止。保留初稿与疑点，不依据和声习惯改读模糊音符；怀疑教材印错时保留原谱忠实转写，另记假设。
- 在查看程序推导前独立标注和弦、转位、用途、和弦外音、乐句与终止式；区分教材明示标签与模型分析，缺少上下文时保留未知。
- 独立参考预期保存在 `.satbt` 的 `reference` 层，`complete=cadence` 仅声明该题终止参考已标全，不代表人工核准。`annotations` 中的谱面提示在非盲推工程中会直接影响推导；**盲推评测前会同时剥离预填和弦、`annotations` 与 `reference`**，仅读取纯四声部音符及题面调号、拍号。

### 2. 双路径推导与自检

通过纯盲推与条件推导两条路径比对分析结果：

- **纯盲推**：仅输入四声部音符与题面调号、拍号，运行和弦与终止式推导。
- **条件推导**：将已知和弦与乐句边界同时作为输入重跑终止式推导。若盲推漏掉某处终止而条件推导将其找回，只能先把排查范围缩小到上游（和弦或分句）；要进一步区分两者，须核对争议拍点，必要时一次仅替换一项输入。

对每处分歧回到原图、自身分析与程序证据，分别归因：
- **转写误读**：音高、临时记号、声部、节奏、延音或题目归属读错。
- **标注有误**：和弦功能、用途、乐句划分、终止类型或范围判断有误。
- **疑似程序问题**：输入可靠，但候选、推导路径或输出存在缺陷或受工具阻塞。
- **口径差异**：同一音乐事实采用不同分段、命名或适用条件。
- **疑似教材错误或上下文不足**：保留双方判断及缺失信息，不强行达成一致。

每次修订转写或候选标注均须保留前值、后值、理由与依据。程序与模型一致不等于正确，不一致也不等于程序错误；不得为提高匹配率篡改原谱或默认参数。

### 3. 确认转写后运行规则检查

教材报错率的读法、应报样本的构造和跨轮汇报约定见[教材规则检查器的迭代约定](./textbook-rule-calibration.md)。

仅在已自检确认转写忠实的范围内运行规则检查，并分别在盲推结果与给定语义工程两条路径上记录诊断。若音符尚未辨清，停留在识读待定状态；多种和声解释会改变诊断结果时，须分别标明各自对应的输入假设。

参考答案可作为可靠起点，但不是绝对正确的证明。规则检查的全部诊断均须进入报告，不得因作品体裁或参考答案身份整体排除诊断。编译失败、未运行、输入受限、规则跳过与零诊断必须分开记录，不能以空数组表示通过。

### 4. 严重程度与理论依据

| 程序层级 | 分析口径 |
| --- | --- |
| 错误 `error` | 采用较严格的斯波索宾标准，逐项核实违反条件与明确例外；不因答案书给出该写法就直接豁免 |
| 警告 `warning` | 同样采用较严格标准，说明上下文、触发条件与例外是否成立 |
| 建议 `suggestion` | 可采用较宽松的教学或审美容差，单列观察教学适切性 |

原始严重程度保持不变，不得以“建议较宽松”或“消除告警”为由自行降级或关闭规则。存在规则口径疑点时，优先检索工作区斯波索宾等《和声学教程》，必要时补充作者、出版社或院校一手网络资料，并记录：
- 书名、版本、PDF 物理页、印刷页、章节与例号（网络资料记录标题、作者/机构与直接链接）；
- 依据要点及其对当前调性、和弦类型/转位、声部、排列与终止位置的对应条件；
- 适用边界与尚未证明部分（一般连接范例不能自动外推至主体终止处）；
- 反向依据或缺失证据，找不到充分依据时明确写明，不得猜造出处。

### 5. 冻结批次、分组与阶段一约束

固化批次清单、输入与参考指纹（SHA-256）、引擎版本、规则档、原始预测与逐题差分，每轮写入新目录。按 `parentQuestion` 划分为**开发集 / 验证集 / 封存集**（同题多解、移调与派生反例随原题归组）：
- **开发集**：第二阶段允许执行层（`Sol`）与编排层（`Astra`）查看逐题错例与详细证据；
- **验证集**：面向执行层保持黑盒，仅输出汇总分数与异常波动告警；
- **封存集**：严格锁定，仅在第三阶段里程碑验收启封一次；后续泛化评估另取从未参与定标的全新原题。

每例报告至少包含定位、环境、谱面确认状态、双方结论、全部诊断（含受限/跳过/异常）、模型归因、理论依据与待审事项。第一阶段不修复程序、不改规则标准或例外、不将候选直接晋升为标准用例。

## 第二阶段：AI 自主迭代闭环

由 `GPT 6.2 Astra` 统筹编排与复核、多个 `GPT 6.2 Sol` 并行执行，需要外部复核时由用户向 `Gemini 4 neon` 转述问题并带回意见。本阶段的核心原则是**严格约束“凭什么声称算法变好了”，同时给予 Agent 充分的过程与架构自主权**：

### 1. 三条核心约定

1. **选题、方法与多智能体调度自主**
   - 优先处理影响多道原题、学生高频遇到、能追到共同根因的问题。
   - Agent 自主决定先读谱抽样还是直接追查代码、如何拆解任务以及何时调用多智能体或外部模型。
   - 一轮工作的有效成果既可以是找出并修复解释几十条警告的共同根因，也可以是证实某类高频警告大多报得准确、从而把精力转向别处。
2. **效果用事先固定的证据检验（以学生默认盲推入口为主）**
   - **数据集隔离**：开发集可反复研究，验证集面向执行层保持黑盒（严禁将验证集具体谱例反喂给执行层调参），封存集严格锁定至第三阶段验收。
   - **改标注与改代码分轮解耦**：代码优化轮锁定 `reference` 只读；转写或参考勘误走独立批次，保留前值/后值/依据，并在新参考上重跑旧版与新版引擎确保曲线可比。
   - **端到端盲推视角与成对回归**：规则与算法改动须同时检验合法写法消除了多少误报、真实错例是否仍能报出以及是否有更多位置被跳过，并配齐最小复现与正反成对回归；**以学生默认使用的纯盲推入口为主要验收视角**，若收益仅出现在给定和弦或单个谱例，须如实写明适用范围。
   - **异常波动主模型复核**：复测出现指标波动、新增诊断或回归失败时，先暂缓合入并交由 `GPT 6.2 Astra` 复核裁定（区分真回归与上游变准引发的良性连带变化并留存归因，严守数据集隔离与争议挂起边界）。
3. **只有真正需要人工裁定的事才进争议池**
   - 凡能靠原谱、教材条文、声部走向或反例查清的问题，由 Agent 查到底；即使两个模型起初意见不同，也可继续核证。
   - 需要外部独立读谱时，由 `Sol` 整理隐去既有结论与程序诊断的中性材料，交由用户向 `Gemini 4 neon` 转发，记录可确认的阅材范围并保存用户带回的意见，再与内部判断对照；由提问者先概括争议机制或给出候选答案的回执记作定向询问。
   - 真正写入**争议挂起池**交由人工的，是证据查清后仍存在合理分歧的取舍——尤其是**教学与产品评分尺度**（例如程序已能准确描述该写法，但教学上应给错误、警告还是建议）、**权威来源冲突、疑似教材印错、多解并存但软件必选单一主标**以及晋升 `StandardCase/Verified/`。个别争议挂起后，其他有充分依据的改进继续推进和分批提交。

### 2. 架构重构与代码卫生授权

Agent 有权在**和弦推导、终止式分析与规则检查**之间调整模块职责，按需要重构、提取共享音乐事实层、整理目录边界或补充辅助工具（详见 [分析模块的代码维护](./textbook-rule-calibration.md#分析模块的代码维护)）：

- **告别单规则堆补丁**：当发现多个入口各自推算同一音乐事实，或修一个谱例需要在多条规则里同步追加例外时，先追查这些判断为何分散，优先将共享事实收口到合适的公共层，避免在单条规则里不断堆叠零散特判。
- **验证与独立提交**：纯重构用已有谱例前后比对确保零意外行为变化（重点留意原先保留的分歧、未分类位置和真实应报点）；若同时修正音乐判断，尽量将结构整理与可观察的行为变化拆为可独立审阅的提交。

### 3. 切入第三阶段的条件

当满足以下任一条件时切入第三阶段：
- 争议挂起池累积足够高影响问题组，或某单一口径阻塞较多开发原题；
- 达到约定的教学试用或发布验收节点，或一组主要失分完成修复并通过冻结复测，已有值得集中复核的结果；
- 准备启封封存集验收泛化或晋升达标样本至 `StandardCase/Verified/`。

## 第三阶段：人工仲裁、盲抽检与里程碑验收

1. **构建轻量人工审计包**：每个待裁定问题收敛为 1 个代表拍点、1 句待裁定问题、一句教材依据（含页码或例号）、受影响原题数、2 至 3 个有实质差异的选项及自填框，附带独立 `.satb` 工程供桌面审计区三视图联动查看，推荐项默认保持未选。
2. **回收回执、口径固化与策略授权**：通过 `audit feedback` 按指纹校验回读 `.audit-feedback.json`，将**条目回答、整谱核准状态与通用方案审批状态**分开记录。单道题目的音乐裁定不等同于修改通用程序策略的授权，涉及通用策略的问题须单独立项审批。经批准的新口径回流第二阶段，指导后续自主迭代。
3. **自主改动与结案盲抽检**：在里程碑按原题、根因与严重度抽少量代表例。同一机制下的多次改动可合并抽样，优先覆盖规则放宽、参考修订及反例不足的规则族，并保留对模型一致处和零诊断位置的抽样。独立记录认可率与置信区间。样本充足且认可率置信下界达到 90% 的类别可降低抽检频率；发现系统性偏差时暂停该类自主权并重查受影响记录。
4. **分母校验、泛化验收与入库**：里程碑验收须先校验按环节执行完成率、全库与独立验收集分母覆盖，再在验证集、封存集或全新未定标原题上对照 M1/M2 目标评估（主分、严格分、原题宏平均、规则分严重度与分来源成绩及纯盲推底线）。仅当某题的谱面转写与预期结论均获**人工核准**且经**复测验证**后，其最终版本方可晋升至 `StandardCase/Verified/`。

`reference complete=...` 只表示参考覆盖完整性，不表示已获人工核准。人工状态单独记录为“待审 / 部分核准 / 已核准 / 退回补证”，方案状态单独记录为“待审 / 通过 / 拒绝 / 已实施”。测试通过或模型一致不能替代任一审计状态。

## Git 与本地材料的边界

- `StandardCase` 默认忽略，只允许目录说明、已有工具示例 `Samples/` 和最终教材用例 `Verified/` 纳入 Git。
- 原 PDF、裁图、转写草稿、候选谱例、逐次运行输出、分析/审计报告、本地工作流与验收规范副本保留在 `Origin/`、`Pilot/` 等本地目录。
- 最终用例只保留复现所需输入、核准预期、必要条件、来源和确认信息；不夹带整批分析过程或重复生成物。
- 人工核准与验证之前不移动候选到 `Verified/`，不强制添加被忽略材料。核准数据不等于已验证程序行为，两步完成后才提交最终版本。
- 应报错反例可作为验证过的最终用例；“已验证”不是“没有诊断”。

## 现有工具与批量评测入口

### 批量评测入口

在仓库根目录运行以下命令。每次指定一个新输出目录，旧版本和新版本可使用同一份清单。

```powershell
npm run benchmark -- --manifest <本地清单.json> --out <新目录>
npm run benchmark -- --manifest <本地清单.json> --out <旧版输出目录> --engine-root <冻结的源码根目录>
```

清单的 `cases` 数组逐题提供 `id`、原题键 `parentQuestion`、转写文件 `sourceFile` 和转写确认记录 `analysisFile`。输入路径以仓库根目录为基准。可同时提供 `sourceSha256` 和 `analysisSha256` 校验冻结的文件。只有原谱明确更换调号时，才在 `printedKeyChanges` 列出题内对应的“小节:拍”位置。盲推剥离预填和弦、`annotations` 与 `reference`，只用四声部和题面节拍、调号。条件终止使用已标和弦与乐句，条件规则还可使用已标终止。缺少连续和弦覆盖而无法使用的终止会写入逐题记录。

和弦按参考覆盖时值评价首选，各原题等权结果另列。终止主分按类型和区间右端一对一匹配，严格分同时核对起点与已标形式、完满性；仅在声明 `reference complete=cadence` 的原题汇总精确率与 F1，全部已知标签命中另列。规则默认报告诊断量。已有独立预期时，可为某题添加如下局部断言。拍位使用从工程起点计的整数 tick，声部集合精确匹配。

```json
{"mode":"conditioned","ruleId":"voice.crossing","tick":0,"voiceIds":["soprano","alto"],"severity":"error","expected":"absent"}
```

把这些对象放入该题的 `ruleAssertions` 数组。`mode` 可选 `conditioned` 或 `blind`，`expected` 可选 `present` 或 `absent`。两条路径各自按严重度统计已核验位置的 TP、TN、FP、FN、无法评分项和剩余未核验诊断。题库缺少应报样本时，召回率为空。

输出包括 `environment.json`、`summary.json` 和 `cases/<id>/` 下的原始推导、参考、输入副本与诊断。比较不同引擎时，核对清单、运行器、输入、规则档与参考内容一致，受限输入和执行异常按环节单列。教材派生的输出和人工待审预期保存在本地忽略目录。

### 转写与审计工具

- [可视化审计区](./audit-workspace.md) 提供教材原图/转写谱对照、问题定位、人工意见保存与导出。模型使用 `npm run audit -- pack` 打包分析条目，`feedback` 读取人工意见；这些工具不运行推导/规则或自动实施修复。
- `.satbt` 编译与文本谱可用于识读、自检和修订记录。
