# 教材规则检查器的迭代约定

教材答案中的正常写法占多数。开发时优先减少学生照谱输入后遇到的误报，同时核实规则仍能指出真实错误。样本由 Agent 查找、构造和复核，人工精力集中在影响教学判断的歧义上。

## 如何衡量改进

- 先按原题确定抽样小节，再运行检查。固定有声小节作分母，包含零诊断小节。纯盲推反映学生实际看到的结果，分别记录每百小节的原始诊断数和经回谱确认的误报数。`error`、`warning` 分开统计，`suggestion` 单列。
- **应静默点**具体到规则、拍位和相关声部。同一拍可以放行一种写法，同时指出另一项错误。对报警处核对原谱，并抽查零诊断位置寻找漏报。转写错误和证据不足的条目单列。
- **真实应报点**取自教材明确指出的错误、正误对照或可用原谱和条文证实的真实错例。**合成反例**由 Agent 从合法片段出发，只改决定规则是否成立的音或声部走向。运行前写下预期规则、拍位与声部，分别记录两类样本的命中数和分母。尚无真实样本的规则，其真实召回率留空。

## 如何处理一组误报

先回原谱核实音符，再对照纯盲推和给定和声标注的结果。若诊断随标注变化，逐项替换和弦或句界以定位上游原因。转写或参考勘误单独成轮。规则放宽时，将应放行的原写法与仍应报的近似错法同时回归，再用同一批冻结输入复测，按根因独立提交。

需要外部复核时，Sol 按[仓库协作规范](../Agents.md)准备中性材料，只向 neon 指明分析范围。记录它实际读到的材料并保存独立判断，再与内部判断对照。已给出候选结论的问答记为定向询问。仍需取舍的教学尺度、来源冲突或模型分歧按根因汇入争议池，到里程碑集中审阅。

## 跨轮执行与汇报

暂停对应当时的目标或用户指明的工作范围。新一轮明确要求继续同一项工作时，按新指令执行。目标已清除时，依当前请求确定任务范围。

日常汇报只写本轮新增的改动、同一分母上的结果和需要决定的问题。已记录的背景按需链接到此处。口径有变时更新对应段落，并说明它影响哪些已有结论。
