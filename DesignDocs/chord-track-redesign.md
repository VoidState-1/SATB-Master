# SATB Master 和弦轨重设计

> 状态：已确认，进入实施
> 分支：`codex/chord-track-redesign`
> 日期：2026-07-25
> 本文只定义设计与实施边界，不代表本轮已经修改工程格式或编辑器行为。

## 1. 背景与目标

当前和弦数据已经包含 `startTick` 和 `durationTicks`，但界面仍接近“位置标记”：只能双击添加，创建后不能在轨道内直接移动、缩放、切分或擦除；显示名称由用户填写，并与结构化字段重复；规则检查也只读取每个和弦区域的第一个时间切片。

本次重设计把和弦轨定义为一条真正的**结构化范围轨**，目标如下：

1. 和弦区域拥有与音符一致的直接编辑能力和撤销语义。
2. 选择、铅笔、擦除、切分工具在和弦轨中具有一致且可预测的含义。
3. 和弦区域明确覆盖一段时间，允许相邻和弦，也允许有意留空。
4. 规则检查在整个区域内使用和弦上下文，并增加和弦进行检查。
5. 显示名称完全由结构化分析和当前调性计算，不允许手工维护第二份名称事实。

## 2. 设计原则

- **意图与实际写作分离**：和弦轨保存用户声明的和声意图，四声部音符是实际写作。规则检查比较两者，但不会静默改写任一方。
- **范围是第一等语义**：和弦从 `startTick` 生效，到 `startTick + durationTicks` 结束；不把下一个标记的位置隐式当作结束时间。
- **同一工具，同一动作语言**：用户不需要为和弦轨重新学习另一套鼠标逻辑。
- **系统生成显示文本**：工程保存结构，界面和 MIDI 导出按需格式化名称。
- **不自动推断和弦**：空白区间仍是合法、明确的“未提供和弦上下文”，不会被自动填充。
- **诊断可追溯**：任何和弦规则问题都必须指向具体和弦区域、时间范围和相关音符。

## 3. 轨道与区域模型

### 3.1 建议的工程结构

工程格式下一次升级时，将当前顶层 `chords: ChordEvent[]` 改为：

```ts
interface ChordTrack {
  visible: boolean
  locked: boolean
  displayMode: 'roman' | 'absolute' | 'both'
  regions: ChordRegion[]
}

interface ChordRegion {
  id: string
  startTick: number
  durationTicks: number
  analysis: {
    degree: 1 | 2 | 3 | 4 | 5 | 6 | 7
    accidental: -2 | -1 | 0 | 1 | 2
    quality: ChordQuality
    inversion: 0 | 1 | 2 | 3
    appliedToDegree?: 1 | 2 | 3 | 4 | 5 | 6 | 7
  }
  locked: boolean
}
```

本阶段不保存 `label`、绝对根音或功能类别：

- `label` 由格式化器生成。
- 绝对根音由区域起点处的调性和结构化分析推导。
- 主、下属、属功能由规则配置推导，避免把特定教材口径固化进工程文件。
- `source`、`confidence` 等推断字段等真正引入和弦推断后再增加。

### 3.2 领域不变量

- `startTick`、`durationTicks` 必须是整数，且区域不得超出工程时间范围。
- 同一和弦轨中的区域不得重叠，但允许相邻，也允许存在空白。
- 三和弦只允许原位、第一转位、第二转位；七和弦才允许第三转位。
- 和弦区域不得跨越调性事件。移动、绘制或新增调性事件造成跨界时，应拒绝操作或由明确命令拆分区域，不能静默改变分析含义。
- 锁定轨道时禁止增删改所有区域；锁定区域时只允许解锁。
- 数组始终按 `startTick` 排序，结束位置统一由起点和时值推导。

### 3.3 空白区间

空白区间表示“没有提供和弦分析”，不是休止，也不是系统推断的前一个和弦延续：

- 不执行依赖和弦的纵向与功能规则。
- 仍执行音域、声部交叉、平行进行等独立规则。
- 检查摘要显示和弦轨覆盖比例与被跳过的规则，不逐格生成缺少和弦的警告。

## 4. 共用工具的交互定义

和弦轨根据指针所在轨道解释当前工具。双击不再创建和弦；在选择或铅笔工具下双击已有区域会选中该区域，并打开浮动和弦调色盘。

| 工具 | 音符区域 | 和弦轨区域 |
| --- | --- | --- |
| 选择 | 单选、追加选择、框选、移动、缩放 | 单选、追加选择、横向框选、移动、缩放 |
| 铅笔 | 单击默认时值，拖动指定时值 | 单击一个网格时值，拖动绘制和弦范围 |
| 擦除 | 点击或连续拖擦，松开后批量提交 | 点击或连续拖擦，立即隐藏，松开后批量提交 |
| 切分 | 在吸附点拆分音符 | 在吸附点拆分区域，两侧保留同一分析 |
| 中键 | 拖动画布 | 拖动画布 |

### 4.1 选择与移动

- 点击区域时选择该和弦，并清除音符选择；点击音符时执行相反操作。
- `Shift` 点击用于追加或移除选择。
- 拖动区域主体只改变时间位置，不存在纵向参数。
- 拖动左右边缘改变起点或终点；起点向前吸附，终点向后吸附。
- 多选移动保持区域之间的相对间隔，只产生一次撤销记录。
- `Delete` / `Backspace` 删除选中区域；锁定区域保留并给出明确提示。
- 左右方向键按当前网格移动；带修饰键的方向键用于调整右边界，具体键位在实现阶段与音符快捷键统一。

### 4.2 铅笔与“和弦画笔”

铅笔工具使用当前和弦画笔：

- 默认画笔是当前调性下的主和弦原位。
- 从已选区域吸取其结构，可连续绘制相同和弦。
- 级数改变时，性质默认跟随调式的常规和弦，但用户可以切换为显式性质以表达副属、借用或变化和弦。
- 单击创建一个当前网格长度的区域；拖动按“左端向前、右端向后”吸附。
- 绘制预览同时显示系统计算的名称和实际时值。
- 绘制提交后立即打开浮动和弦调色盘；调色盘修改当前区域时同步更新和弦画笔，便于连续输入同类结构。

首版不采用“画过既有区域就覆盖”的行为。绘制只能占用空白区间，遇到相邻区域时预览边界钳制到最近边界；替换必须先擦除，避免静默丢失分析。

### 4.3 碰撞与边界

- 移动和缩放预览被工程边界、调性边界和相邻和弦边界共同限制。
- 如果整个多选无法保持相对关系地移动，则保持原位并说明阻塞原因。
- 最短区域长度为当前吸附网格。
- 相邻区域可以共享边界，不自动合并；即使分析相同，也保留用户划分的和声节奏。
- 拖拽过程只更新临时预览，鼠标释放后提交一个领域命令。

### 4.4 复制、粘贴与切分

- 音符选择和和弦选择互斥，剪贴板负载使用可区分的事件类型。
- 复制多个和弦时保留相对时间、时值、结构和锁定之外的属性。
- 粘贴以播放头为最早区域起点；发生重叠或跨调性边界时整体拒绝，不做部分粘贴。
- 切分后左侧保留原 ID，右侧获得新 ID；两个区域结构相同且均未锁定。

## 5. 显示与属性编辑

### 5.1 轨道视觉

- 和弦区域绘制为有明确左右边界的横向块，而不是最小宽度位置标签。
- 选中态使用清晰描边；左右 6 px 为缩放命中区；锁定态同时使用图标或纹理，不能只改变颜色。
- 区域太窄时优先显示罗马数字，完整信息放入悬浮提示与属性检查器。
- `both` 模式使用两行紧凑显示：上行罗马数字，下行绝对和弦；轨道高度随显示模式稳定切换。
- 播放头所在和弦和当前选中和弦可在钢琴卷帘中显示很淡的范围底色，但不得遮盖音符、锁定区间或诊断标记。

### 5.2 属性检查器

删除“显示名称”输入框，保留以下结构化字段：

- 级数与级数变化音。
- 性质。
- 转位。
- 副属目标。
- 起点、时值与锁定状态。

检查器顶部只读显示系统计算结果，例如：

```text
V7/V
D7
属功能 · 指向 V 级
```

多选时只显示共同字段；修改共同字段形成一个批量命令。显示模式属于轨道设置，不属于单个和弦。

### 5.3 浮动和弦调色盘

- 调色盘采用紧凑五列布局，依次编辑级数、变化音、和弦性质、转位和副属目标；分类与工程结构一致，不复制其他软件的和弦模型。
- 顶部同时显示系统计算的罗马数字和绝对和弦名，所有选项只修改结构化字段，不保存自由文本名称。
- 绘制和弦完成后自动打开；选择或铅笔工具下双击已有区域重新打开。锁定区域和锁定轨道不进入快速编辑。
- 点击外部、按 `Escape` 或点击关闭按钮退出；右侧属性检查器仍作为持续编辑和时间参数编辑入口。
- 浮窗根据窗口边缘自动调整位置，并在窗口缩放时重新计算；不包含钢琴键盘、MIDI 输入或其他与和声分析无关的区域。

## 6. 系统命名

### 6.1 单一事实来源

名称格式化器输入为：

```ts
formatChord(region.analysis, keyAtTick, displayPreferences)
```

输出至少包含：

```ts
interface FormattedChordName {
  roman: string
  absolute: string
  functionLabel?: string
  spokenDescription: string
}
```

所有消费者共用该格式化器：和弦轨、属性检查器、诊断消息、MIDI Marker 和测试快照。禁止各处自行拼接名称。

### 6.2 罗马数字规则

- 大三和弦使用大写， minor/diminished 使用小写，增三和弦添加 `+`，减和弦添加 `°`，半减七添加 `ø7`。
- 变化级数使用 `♭` / `♯` 前缀，例如 `♭II`、`♯iv°`。
- 三和弦转位使用空、`6`、`6/4`；七和弦使用 `7`、`6/5`、`4/3`、`4/2`。
- 副属目标使用斜线，例如 `V7/V`。
- 性质是结构化事实，罗马数字大小写只是它的显示结果，不反向推断或修改性质。

### 6.3 绝对和弦规则

- 根音拼写必须结合调号和音级字母推导，不能只用 pitch class 查一张固定升降号表。
- 转位使用实际低音拼写，例如 C 大调 `ii6` 显示为 `Dm/F`。
- 副属和弦先在目标音级的临时调性上下文中计算根音。
- 首版使用系统的调性拼写；未来若增加等音偏好，只保存全局显示偏好，不保存单个区域的自由文本覆盖。

### 6.4 示例

| 调性与结构 | 罗马数字 | 绝对和弦 |
| --- | --- | --- |
| C 大调，I，大三，原位 | `I` | `C` |
| C 大调，ii，小三，第一转位 | `ii6` | `Dm/F` |
| C 大调，V，属七，第二转位 | `V4/3` | `G7/D` |
| C 大调，V/V，属七，原位 | `V7/V` | `D7` |
| C 大调，降 II，大三，原位 | `♭II` | `D♭` |

## 7. 和弦范围内的规则检查

### 7.1 时间切片

规则检查的边界集合包含：

- 和弦区域起点与终点。
- 四声部音符起点与终点。
- 调性事件位置。

每个切片都查找覆盖该时间的和弦区域。当前实现按和弦 ID 去重、只检查第一个切片的逻辑必须移除。

### 7.2 和弦外音

首版采用可解释的严格基线：

- 任何与和弦区域重叠、且 pitch class 不属于该和弦构成音集合的音符片段，产生“和弦外音待确认”诊断。
- 同一音符在同一区域内连续跨越多个切片时合并为一条诊断。
- 诊断范围取音符与和弦区域的交集，并同时关联音符 ID、声部和和弦区域 ID。
- 默认严重度为 warning；经过音、辅助音、倚音、延留音等可能合法，因此首版不直接判为 error。
- 后续可增加非和弦音分类器或人工角色标注，再根据上下文降级或消除提示；在有金样本前不静默猜测。

持续音跨越和弦边界时会分别接受两侧和弦检查。这能识别真正的不协和，也意味着延留音会被明确提示，符合“先发现、再解释”的学习目标。

### 7.3 构成完整性、转位与重复音

- 每个有效切片检查构成音集合、低音与转位、导音重复等规则。
- 连续切片得到相同结论时合并诊断，避免一个长区域刷出大量重复问题。
- 四声部不完整时，跳过需要完整纵向结构的规则，并在检查摘要计数。
- 和弦七音的解决跨区域检查实际声部进行，不依赖手写名称。

## 8. 和弦进行与逆功能进行

### 8.1 功能分类

功能不写入工程，而由 `RuleProfile` 中可测试的映射表计算：

```ts
type FunctionClass = 'tonic' | 'subdominant' | 'dominant' | 'other'
```

映射需要考虑调式、级数、性质、变化音和副属目标。具体哪些和弦属于主、下属、属功能，以及哪些例外允许，必须在选定《和声学教程》的版本后形成带出处的规则表。

### 8.2 连接检查

- 只检查时间上直接相邻的两个已知区域；中间存在空白时不跨越空白推断进行。
- 调性变化中断旧调的功能链；换调后的第一个区域从新上下文开始。
- 同功能延续不视为逆功能进行。
- 初始规则将教材定义的逆功能连接标为 warning，而不是 error。
- 副属和弦增加“目标解决”规则：例如 `V/V` 应在允许窗口内进入 V 级或规则表允许的替代连接。
- 诊断关联前后两个和弦区域；点击问题项时同时高亮二者，并定位到连接边界。

这里不应直接把 `D -> S` 等简化公式硬编码为唯一真理。最终矩阵需要区分基础练习、序进、终止式、经过性和弦和调性变化等上下文，否则误报会迅速削弱教学价值。

### 8.3 建议的首批规则

1. 和弦外音。
2. 和弦构成不完整。
3. 低音与转位不一致。
4. 不恰当的导音重复。
5. 七音解决。
6. 逆功能进行。
7. 副属和弦未进入目标。
8. 和弦区域跨调性边界或结构无效。

## 9. 诊断与导航

`HarmonyDiagnostic` 需要增加 `chordIds: string[]`，不能再只能关联音符：

- 纵向问题关联一个和弦和相关音符。
- 进行问题关联前后两个和弦，可不关联音符。
- 问题列表点击后选中和弦区域并把时间轴滚动到诊断边界。
- 和弦块底部使用与音符一致的错误/警告色条。
- 检查摘要显示：总时长、已标注时长、覆盖率、执行规则和因缺少上下文跳过的规则。

## 10. 领域命令

和弦编辑必须从 `App.tsx` 中的直接数组修改迁移到纯领域命令：

- `addChordRegions`
- `transformChordRegions`
- `resizeChordRegion`
- `deleteChordRegions`
- `splitChordRegion`
- `updateChordAnalysis`
- `setChordTrackState`

每个命令统一负责整数时间、范围、重叠、调性边界、锁定和排序校验，并返回与音符命令相同的 `EditResult`。React 只处理临时预览、选择和错误展示。

## 11. 工程迁移与 MIDI

### 11.1 schema v1 -> v2

- `chords[]` 迁移到 `chordTrack.regions[]`。
- 现有平铺的 degree、accidental、quality、inversion 移入 `analysis`。
- 旧 `label` 不再作为活动字段；迁移后由系统重新计算显示。
- `visible`、`locked` 使用安全默认值，显示模式默认 `roman`。
- 迁移前后必须保持 ID、起点、时值、结构和锁定状态。
- 对旧工程中的自定义名称变化提供一次迁移说明，但不继续保存自由文本覆盖。

### 11.2 MIDI 导出

MIDI Marker 没有标准的范围时值字段，因此：

- 每个区域起点写入系统生成的罗马数字 Marker。
- 区域结束后若存在空白，写入 `N.C.` Marker，避免导出后被误解为持续到下一个和弦。
- 相邻区域的下一个 Marker 自然结束前一区域。
- MIDI 导出与界面必须调用同一名称格式化器。

## 12. 分阶段实施

### 阶段 A：模型、命名与迁移

- 新建 `ChordTrack` / `ChordRegion` 模型和 v1 -> v2 迁移。
- 实现调性相关的罗马数字、绝对和弦与低音拼写。
- 将 MIDI 与诊断消息切换到统一格式化器。
- 为合法结构、转位边界、调性拼写和迁移建立领域测试。

### 阶段 B：领域命令与轨道编辑

- 实现和弦区域增删、移动、缩放、批量、切分和锁定命令。
- 让四种工具在和弦轨中生效，移除双击添加，并提供绘制完成与双击触发的浮动和弦调色盘。
- 增加临时预览、碰撞钳制、键盘编辑、复制粘贴和单次撤销。

### 阶段 C：范围规则

- 修正时间切片与全区域检查。
- 增加和弦外音合并、构成完整性、转位、重复音和七音解决测试。
- 扩展诊断以关联和弦 ID，并完成问题面板导航。

### 阶段 D：功能进行

## 13. 首版验收标准

- 用户无需切换专用工具即可绘制、选择、移动、缩放、擦除和切分和弦区域。
- 新建区域和双击已有区域均可直接使用五列调色盘编辑结构，名称即时由系统重新计算。
- 所有拖拽只产生一次撤销；锁定、重叠、工程边界和调性边界不可被绕过。
- 工程文件不再保存手写显示名称，界面、诊断和 MIDI 名称一致。
- 和弦区域内每个实际音符片段都参与和弦成员检查，连续重复诊断被合并。
- 相邻和弦能够执行有出处、可配置并有正反例的功能进行检查。
- 空白区间不被自动填充，规则摘要准确说明未执行部分。
- v1 工程迁移后时间、结构和锁定信息不丢失。
- 本地生产 Electron 端到端流程覆盖核心和弦轨编辑与规则反馈。

## 14. 已确认的产品决定

2026-07-25 已确认：

- 区域不重叠，允许空白。
- 碰撞时钳制，不覆盖既有区域。
- 铅笔使用可复用的当前和弦画笔。
- 默认罗马数字单行显示，可切换绝对或双行。
- 和弦外音默认为 warning，并允许未来分类。
- 功能进行只跨直接相邻区域检查。
- 和弦区域不允许跨调性事件。
- 首版包含和弦多选、复制与粘贴，并保持单次撤销语义。
- 逆功能进行采用国内常见斯波索宾版《和声学教程》的基础功能序进定义；实现中以独立规则配置和正反例固定口径。
- 允许用户给音符人工标注经过音、辅助音、延留音等非和弦音角色；明确标注后不再生成未分类的和弦外音提示。

斯波索宾规则的首轮范围限定为基础功能序进与副属目标解决。序进、离调扩展、复杂终止式等需要更多上下文的例外，后续按带出处的独立规则增补，不扩大首版的推断范围。
