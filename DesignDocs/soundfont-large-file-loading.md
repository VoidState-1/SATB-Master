# 大型 SoundFont 加载设计

## 目标

- Windows x64 桌面端允许最大 2 GB 的 SF2/SF3 文件。
- 不再通过 Electron IPC 返回完整文件字节，避免主进程、预加载桥和渲染进程各自保留大块副本。
- 加载前检查可用物理内存，并向用户显示文件大小、建议可用内存和加载进度。
- 保留用户音色的 SHA-256 工程引用校验及默认音色的发行摘要校验。

## 数据路径

1. 主进程检查扩展名、文件状态、2 GB 上限和可用内存。
2. 主进程签发最长 15 分钟有效的短时随机资源令牌。
3. 渲染进程通过 `satb-soundfont://resource/<token>` 流式读取文件，并直接写入一个按文件大小预分配的 `ArrayBuffer`。
4. 主进程同时使用文件流增量计算 SHA-256，只保留小块读取缓冲区。
5. 读取和校验完成后立即释放令牌；完整 `ArrayBuffer` 交给 SpessaSynth AudioWorklet 时使用可转移所有权。

自定义协议只接受随机令牌，不接受本地路径。协议处理器会在传输前复核文件大小和修改时间，防止预检后文件被替换。

## 内存策略

- 文件硬上限：`2 * 1024 * 1024 * 1024` 字节。
- 32 位构建仍拒绝超过 512 MB 的文件；当前发行目标为 Windows x64。
- 建议可用物理内存：`文件大小 * 1.5 + 512 MB`。
- 可用物理内存低于建议值时拒绝加载，避免进入解析阶段后才因连续内存分配失败而崩溃。
- 换音色时先释放旧 SoundFont，再读取新文件，避免两套采样同时驻留。

该估算覆盖 SF2 原始采样、解析结构、工程和系统余量。SF3 解码后的实际内存可能明显高于压缩文件大小，因此 2 GB 是允许上限，不代表任意机器都能加载该大小。

## 验证范围

已验证：

- 2 GB 容量边界、超限、32 位限制和内存不足的自动测试。
- 流式字节组装、长度变化检测、类型检查和生产构建。
- 生产模式 Electron 中的默认 SoundFont 预载、实际发声、用户音色摘要、工程重开和重新加载。

尚未验证：

- 真实 2 GB SF2/SF3 的解析峰值内存、耗时和连续播放稳定性。
- Windows 11 及不同物理内存容量机器上的动态阈值表现。

发布前应使用来源和许可证明确的 512 MB、1 GB、1.5 GB、2 GB 测试音色记录峰值专用内存、加载耗时和 AudioWorklet 稳定性，再决定是否调整 `1.5 倍 + 512 MB` 的预检公式。
